## Compression Speed and Ratio
- **Zstandard** compresses roughly 3 times faster than gzip at default levels and decompresses at speeds of 1-2 GB/s compared to gzip's 300-400 MB/s. This makes zstd highly suitable for real-time applications and workflows requiring frequent compression and decompression.
- **Gzip** is slower because it was designed in an era prioritizing storage over CPU cycles.
- Compression ratios are comparable at similar speed settings, but zstd offers a wider range of compression levels (1-22) compared to gzip (1-9), allowing more granular control over speed vs size trade-offs.
- At higher compression levels, zstd can match or exceed compression ratios of more intensive algorithms like bzip2 while maintaining faster decompression.

## Compatibility and Support
- **Gzip** is supported universally by all operating systems, browsers, web servers, and CDNs. It is the default and safest choice for public-facing web content.
- **Zstandard** support has grown rapidly since its introduction in 2016. It is supported by modern browsers like Chrome (since version 123) and Firefox, as well as web servers like nginx and Apache. However, older systems and some embedded devices may lack support.
- For HTTP content encoding, gzip remains the most widely supported, but zstd is gaining adoption, especially for internal or controlled environments.

## Practical Use Cases and Trade-offs
- Use **gzip** when maximum compatibility is required, such as serving unknown clients or public web content.
- Use **zstd** when speed and efficiency are critical, such as in internal microservices, database backups, CI/CD artifact caching, container image layers, or real-time data pipelines.
- Many setups use zstd for modern clients with gzip as a fallback for compatibility.
- Zstd supports dictionary compression, which can significantly improve compression for small, similar files (e.g., JSON API responses), a feature gzip lacks.

## Additional Notes
- Brotli is another modern compression algorithm that often compresses better than gzip and zstd but at a higher computational cost, especially at high compression levels.
- CDNs and web servers vary in their support and default settings for these algorithms, so understanding your infrastructure is important.
